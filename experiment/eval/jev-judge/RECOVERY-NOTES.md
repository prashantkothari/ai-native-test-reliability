# Recovery notes

This directory was rebuilt from a Claude conversation transcript after another
session ran `git worktree remove --force` on the worktree holding the original
work, without checking for uncommitted changes first. None of this had ever been
`git add`ed or committed, so the deletion took it with it. This file documents
exactly what came back verbatim vs. what's reconstructed vs. what's genuinely gone.

## Full recall — exact content, reconstructed line-by-line from Write/Edit tool calls in the transcript

All `.mjs` source files, `lib/*.mjs`, `package.json`, `.gitignore`, `fixtures/base.html`,
`results/inline-llm-judgments.json`, `results/choice-verdict.md`, `results/jev-plan-review.json`.

## Regenerable, not stored — `cases/manifest.json` and `cases/case-*.html`

These are deterministic output of `generate-cases.mjs` + `lib/mutate.mjs` given
`fixtures/base.html` and two fixed RNG seeds (42 for the drift-kind shuffle, 7 for
decoy left/right positioning). Since the generators are fully recovered, running:

```bash
npm install
node generate-cases.mjs
```

reproduces these 20 files byte-identical to the originals. Not committed as static
files — commit them after generating, or leave them as a build step.

## Reconstructed, not byte-identical — `fixtures/prevalidate-5kb.html`

The original was generated by an inline throwaway Python script (60 filler buttons
+ a form, padded to ~5KB) to smoke-test that the Jev API accepts a DOM blob of that
size. The file here is regenerated from the same recipe and is structurally
equivalent (same shape, same approximate size) but not a byte-for-byte match —
the original's exact button count/attributes weren't preserved in the transcript.
Fine for its actual purpose (a size/shape probe), not meaningful as data.

## Partial recall — `results/jev-run-results-unlabeled-decoy.json` and `results/choice-run.json`

These are records of live, non-deterministic API calls (Jev's `Noul` and `Choice`
primitives). What's exact vs. missing:

**Exact, for every one of the 20 cases in both files:**
`id`, `control_type`, `drift`, `truth_index`, `baseline.correct`, and the judge's
`top_prob` / `confidence`, `abstained`, `correct`, `wrong_confident` — these were
printed to the console during the original runs and are copied verbatim from the
transcript.

**Exact, for the 6 `decoy-insertion` cases only, in `choice-run.json`:**
The full 8-element `probabilities` array — these were explicitly printed in a
follow-up inspection command during the original session (the "tied vs. uniform"
check) and are reproduced exactly. `argmax_index` for the corresponding cases in
`jev-run-results-unlabeled-decoy.json` was then derived from these (both scripts
share the same deterministic `rank()` call on the same case HTML, so candidate
index 0/1 refer to the same two elements in both files for a given case).

**Set to `null` (genuinely not recoverable from memory) in both files, for every case:**
`probabilities` (for the 14 non-decoy cases in `choice-run.json`), `latency_ms`,
`tokens_in`, `tokens_out`. Per-case token/latency granularity was never printed to
console in the original run — only the following **aggregates** are known and were
reported at the time:

- Jev-Noul (`run.mjs`, 160 calls across 20 cases): **180,419 input tokens / 3,360 output tokens**, median per-judgment latency ≈385ms.
- Jev-Choice (`judge-choice.mjs`, 20 calls): **31,985 input tokens** (≈18% of Noul's), no separate output-token or latency aggregate was recorded beyond what's in `choice-verdict.md`.

**Consequence for `compare.mjs` and `metrics.mjs`:** every correctness/abstain/
wrong-confident number and table these scripts print will match the original
findings exactly. The one line that will NOT be trustworthy from these recovered
files alone is the token-cost line in `compare.mjs`'s "Cost check" section — it
sums per-case `tokens_in`, which are `null` here, so it will print `0` instead of
the real aggregates above. Use the aggregates quoted here (and in
`results/choice-verdict.md`) for that comparison, or re-run the live harness for
fresh, complete per-case data (this is explicitly Phase 2 — see the recovery
request this rebuild responded to).

## Not recovered at all

The exact raw JSON response bodies from the ~340 individual live API calls made
during the original session (full Jev/Choice response objects beyond what's
described above). Re-running `run.mjs` and `judge-choice.mjs` against the live
API is the only way to get these back.
